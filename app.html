VerGate

Type an npm-style version range and a list of versions. See which ones get through, and why the others do not.

Sort by precedence and bump

Follows the semver.org 2.0.0 precedence rules (numeric parts compared as numbers, a pre-release sorts below its release, numeric identifiers sort below alphanumeric ones, build metadata ignored) and the range grammar of npm's semver package. Fixtures (1313 checks) were produced by running npm semver 7.8.5 over 44 ranges and 28 versions. The pre-release rule matches npm: a pre-release like 1.3.0-beta.1 only satisfies a range if one comparator in that same part of the range names a pre-release on the same major.minor.patch. The expanded form shows npm's normalisation, where an upper bound such as <2.0.0-0 means "below any 2.0.0 pre-release". Other ecosystems (Cargo, pip, Maven, Composer) use different range rules. Strict versions only: 1.2 and 01.2.3 are not valid semver, and a leading v is accepted. Runs in your browser, nothing stored.
